Что даёт

Нечего мониторить, патчить и масштабировать. Нагрузку раздаёт CDN, данные отдают открытые API.

Нечего утечь

Нет базы, нет аккаунтов, нет секретов. Прогресс игрока остаётся в его браузере.

Деплой = тег

Откат — на предыдущий тег. Форк — и у тебя своя копия игры, тоже бесплатно.

Этот блок не про агентов, а про архитектуру в целом. Публичные API без ключей с CORS превращают браузер в полноценный клиент к данным всего мира. Сервер нужен, только если надо хранить чужие данные или прятать ключи. Здесь не надо ни то, ни другое. ~2 мин.

чтобы это работало, а не падало

Цена: ты гость в чужой инфраструктуре

  • Только API без ключей. Ключ в статике сразу становится публичным
  • Уважай usage policy. Nominatim: 1 запрос в секунду; Overpass отвечает 429
  • Кеш обязателен. Город, загруженный один раз, живёт в IndexedDB
  • Зеркала и таймауты. 3 Overpass-зеркала, 30 с, протухший кеш как запасной
  • Честный fallback. Нет рельефа → плоская земля; нет OSM → процедурный лес
  • Атрибуция. Данные OSM под ODbL, © OpenStreetMap contributors

И бонус для агентов

Нет сервера → нет миграций, окружений и секретов. Агенту можно доверить релиз целиком.

Границы слоёв записаны в AGENTS.md: geo/ не знает про Three.js, world/ не знает про сеть.

Подвох бессерверной архитектуры: твоя доступность — это доступность чужих бесплатных сервисов. Отсюда кеш, зеркала и fallback на каждом шаге. Это паттерн, применимый далеко за пределами игр: дашборды, карты, визуализации открытых данных. ~2 мин.

почему VM, а не просто облачный агент

Для корпоративной разработки

Периметр

Код и токены не уезжают из сети организации. VM — граница изоляции, агент спокойно гоняет docker compose.

Секреты

Креды провайдера лежат в файле с правами 0600. В tmux уходит только имя провайдера, в ps их не видно.

Грабли Bedrock

Без закреплённых моделей алиас opus тихо падает на младшую модель. WebSearch там недоступен.

Один bootstrap-скрипт, идемпотентный. Спека 15 августа, рабочая версия через две недели. Тоже с агентом.

Узкое место сместилось

С «написать код» на «проверить результат».

Агенты пишут быстрее, чем я успеваю посмотреть. Ревью и визуальная проверка — это теперь главная работа человека.

Все три примера записаны в разделе 0 дизайн-документа. Ни один unit-тест их бы не поймал, нужен был глаз. Поэтому стоит строить инструменты, которые сжимают проверку: контактный лист, boot-check, отладочный readout в паузе. ~2 мин.

возвращаемся к вопросу про вериги

Medium или x-high: зависит от класса задачи

класс задачипримергипотеза
Исполнение по планузадача из плана с готовыми тестамиmedium ≈ x-high, а часто хватает и GLM/Kimi
Механика по образцуещё одна машина, ещё один вид гриба в YAMLmedium ≈ x-high
Диагностиканевидимая стена на набережной, третий разx-high окупается

Пять правил

  • Спека до кода. Агент исполняет план. Пустой промпт порождает импровизацию
  • Контракт в репозитории. AGENTS.md / CLAUDE.md, инварианты, грабли. Агент не помнит, репозиторий помнит
  • Проверка запуска, а не только тестов. boot-check ловит то, что зелёный CI пропускает
  • Один агент — один worktree. Без этого параллельность превращается в конфликты
  • Инструменты для глаз. Сжимайте ревью: контактные листы, readout, 👀 в changelog
Главный слайд для практиков. ~1.5 мин.
